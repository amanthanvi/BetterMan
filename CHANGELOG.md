# Changelog

All notable changes to BetterMan are documented here.

## Unreleased

- Ingestion: the distro containers and the FreeBSD job can install the ingestion package again. Since `ingestion/data/` was added (#436), `pip install` found two top-level packages and stopped, which would have failed every curated distro's ingest. The package is now named explicitly, and CI checks that pip can install it.
- Security: the `zod` 3.22.4 that the pinned Vercel CLI's backend and Python builders use resolves to 4.6.7, since no 3.x release fixes GHSA-mrhx-c7xc-m3w5; those builders parse Python manifests identically under both. The `ip-address` under `sigstore`, which `deps:provenance` uses, resolves to 10.7.5 (GHSA-rxp7-6hxx-x8q5). Scorecard's Vulnerabilities check had reported both.
- Dependencies: Next.js and `eslint-config-next` 16.4.3. Next 16.4.3 no longer loads the app-page runtime into `proxy.ts` and keeps OpenTelemetry request traces together. CodeQL's `init` and `analyze` move to 4.39.1, the release `upload-sarif` already used.
- Browse (C5, #407): section pages always show A–Z; a letter on the page jumps to its group and any other starts a page at that letter (`/section/1?from=t`, a new `from` boundary on the section listing). One field filters the names on the page as you type and searches the whole section on Enter or without JavaScript. Sections link to each other, and the lede names the range shown. Package pages (`/pkg/<name>`) take the print-manual design: running head, mono name, version lede, and a ruled list of the package's manual pages.
- Search as home (C5, #407): typing in the home box shows results inline under it (`/?q=…`, noindex), with a living placeholder that stays still under reduced motion; without JavaScript the box opens `/search`. Recent and Bookmarks appear only once they have entries (or when asked for by `/#recent` / `/#bookmarks`). A full page load of `/?q=` goes to `/search`. Results give one line of evidence per hit and small-caps kinds, including `task`: worded queries such as "how do I extract a tarball" now match B6 task phrases through a release-scoped task index (`manPageTaskPhrases`, backfilled per active release on activation and after each deploy, with `pnpm convex:task-check --prod` reporting completion) and cite the phrase. The top hit leads with one sourced example and its gloss (tldr-pages with CC BY 4.0), an "Explain this line" link, then its key flags from verified usage and its package. A pasted command line is offered to explain. The search page drops its display heading and its section-listing read.
- Explain (C5, #407): `/explain?cmd=…` is now the explain page, server-rendered and complete without JavaScript (the share URL no longer returns JSON; `/api/v1/explain` still does). On a phone it reads command, then each command's NAME line, then the numbered token grid. A flag cluster such as `-xzvf` is one cell whose flags are separate links, each opening one definition at a time in a dismissible card that pins under the header on phones. Every flag links to its exact definition and shows GNU/Linux · FreeBSD · macOS cells from the derived summary (`portability.getCells`). The safety note shows the engine's fixed command facts only; the page adds no claims. Counts the `explain used` event. Explain pages, explain API answers and any URL with typed `cmd`, `q` or `name` (search and type-ahead included) are never kept in the service worker's caches, and Sentry redacts `cmd`, `q` and `name` from request URLs, query strings, Referer, breadcrumbs, spans and envelope headers. On phones the definition card is fixed under the header, and long tokens wrap.
- Man pages (C4, #406): a command composer (pick flags from the options index with hover/focus/tap-only add controls, type each argument rather than copying the manual's notation, and get portability and exclusive-mode warnings before copying); cross-reference previews on hover and keyboard focus; and live reference tables (find a row, sort columns, never hiding rows), such as ascii(7).

- Man pages (C4, #406): In brief replaces the examples preview. It is the generated summary, sourced examples (the page's EXAMPLES, then tldr-pages credited under CC BY 4.0 with the change notice, then verified generated examples, each labelled) and the most-used flags counted from verified examples, grouped "One mode · Then add" where the page defines modes. Each part is omitted without data. The index of options gains a "Portable only" filter, `?portability=text` words for the portability cells, and "new in <version>" marks; its filters never hide manual text.

- Man pages (C4, #406): `/man/<name>/<section>` and `/man/<name>` are rendered as plain server HTML with no Next runtime. The only scripts are one hashed inline boot script (theme, reading preferences and distro before first paint) and a 47 KB (15 KB gzip) static bundle, against 636 KB (203 KB gzip) of JavaScript before. HTML falls from 109 KB to 51 KB on the long-page budget fixture, and code blocks are highlighted on the server. Man pages run under a hash-only CSP with no nonce, and their HTML can be cached at the edge per dataset release: the proxy keys each response on the active release and sends readers whose default distro is not Debian from a bare URL to the explicit `?distro=` URL, privately. Misses answer a real 404 with man's voice, suggestions and other distributions in the markup. Every feature carries over: find, the pager keys, option selection, contents, the palette, preferences, bookmarks, history, the distro picker, short URLs and analytics events. The reader's preferences now sit on `<html>` on man pages.

- Generated layer (B6, #398): man page responses carry a `brief` with a one-sentence summary, up to five examples (the manual's own EXAMPLES, then tldr-pages, then generated examples only to fill the gap to three) and three to five task phrases. tldr-pages is pinned to one upstream commit with a page digest, attributed under CC BY 4.0 on `/licenses` and on every tldr example, and every example is kept only when each of its flags exists in that page's own options table (clusters such as `-xzf`, `tar czf`, pipelines and `git commit` subcommands included); over cached Debian pages 86% of 2,512 tldr examples verify. The verifier reads commands with a quote-aware lexer and rejects substitutions, subshells, heredocs, wrapped or indirect invocations placeholders in a command position, and placeholders that are neither a flag list nor plain value words; value alternations such as `{{tagged|untagged}}` show their first choice. Model text comes from DeepSeek V4.1 Flash through OpenCode Go behind a swappable OpenAI-compatible client, with a versioned prompt, a strict JSON schema, the same flag verifier, and provenance (provider, model, prompt version, date). A generated example must be exactly one simple command that runs the page's own command, and destructive commands (rm, dd, mkfs, ...) get no model text at all. Stored text is plain text: control and bidi characters are rejected, and readers render it as text only. Rows are stored once per page content hash in `manPageGenerated`, so text is regenerated only when a page changes, and a page view adds one indexed read. A `generated-layer` workflow runs the indexed tier within Go's 5 h, weekly and monthly caps through a budget governor that meters every HTTP attempt, retries included, and charges the worst case whenever usage is incomplete, and a ledger recovered only from this workflow's scheduled or dispatched default-branch runs (the run fails closed when the newest recent ledger cannot be recovered), and is a dry run until the owner adds `OPENCODE_GO_API_KEY`. The reader renders the brief in C4 (#406). See `docs/generated-layer.md` and `docs/runbooks/generated-layer.md`.

- Design: BetterMan 2's print-manual system (#405). The manual is set in BM Text, a Source Serif 4 subset under the OFL, split into Latin, Latin Extended, Greek (monotonic) and Cyrillic files; polytonic Greek and other scripts fall back through a serif stack. BetterMan's own text uses the system sans, and anything typed uses the system mono. Geist and JetBrains Mono are no longer served, which cuts preloaded font bytes from 136 KB to 53 KB. New tokens (paper, added, ink, rule, one red) replace the old palette, with light and dark as before. Every page now has running heads in small caps, hairlines and square corners. The header shows the `betterman(1)` wordmark, a search control and a single theme glyph. Man pages get hanging section numbers, a running foot, troff hanging indents with option terms in bold mono, an index of options with section locators and a filter that never hides manual text, examples and the See also / Related addendum on a tint, and text actions (Find, Preferences, Bookmark, Copy link). A portability glyph is ready for flag data. Search results carry small-caps kinds (`flag` replaces `options`). Where a manual is rendered, the pager keys `/`, `n` `N` (resuming from the last match after find closes), `j` `k`, `g` `G` and `[` `]` work as in less, with `j` `k` `g` `G` moving at once rather than smooth-scrolling; on a man-page 404 and everywhere else `/` still searches, and the existing shortcuts stay. Anything typed into a field is mono. Reading text now defaults to the serif at 18px, and readers who chose sans or mono keep their choice. Robustness: scrollable code and tables take keyboard focus with a label, the contents list is valid list markup, and controls that need JavaScript are hidden without it. The options index opens through a native disclosure and the header search falls back to a link, so every page works without JavaScript. `pnpm next:grammar` enforces the new grammar, and `DESIGN.md` and `PRODUCT.md` record it.
